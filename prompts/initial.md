# Context

You are a database and presentation/visualization expert. I've started to create the content for a presentation on the development of databases. The talk has 2 core ideas: First, explain how environmental requirements lead to inventions (such as storing counts on a bone) or having a sortable index on cards. Second, it relates to Michael Stonebreaker's paper ("what goes around comes around ... and around") trying to explain why SQL and the relational model have absorbed many other database developments. 

You'll find the existing material in the "docs" folder. Please review it carefully.

# Task

Your task is to create an interactive HTML-based presentation that can be used in full-mode in a browser during presentation. The key theme is to playfully and interactively explain core database concepts by understanding the origins. It is important to understand the problems that were intended to be solved.

# Modes

There are two modes for the presentation. First, "presentation" mode. It leads the speaker from landing page, to timeline, through every milestone (and transition) to the big picture. Going forward is possible via mouse click or forward arrow button press. Going back is by backward arrow button press. In presentation mode, content incrementally shows up, not everything is viiable when entering  timeline and milestone pages. Rather, for timeline, each milestone appears on after another on the timeline. For milestone, see instructions below. Second, "exploration" mode, everything is simply visible. Add toogle to switch between presentation and exploration mode. Hide the toogle by default. 

# Views

## Landing Page

Create a landing page that clearly outlines the 2 core ideas of the talk (maybe just a few words or a phrase together with an illustrative image)

## Timeline

The main view is a timeline covering all milestones. The timeline should have 2 scales, a linear metric scale keeping distances correct, and a logical scale, putting the milestones together in equal distances for better readability. The scale should be togglable. Each milestone is represented as an image/symbol along with its year. Timeline should be zoomable. Morever, going to the start and end with a single button press should be possible.

- Use the entire space to have the timeline as large as possible. 
- Add important vertical markers such as 0bc and the invention of writing

## Milestone

When clicking on a milestone on the timeline view, a detailed view should become visible. Each milestone view should contain an image that exemplifies it. Moreover, the key take away should be present as text. Also, each milestone should have an interactive mini game that helps the audience to playfully understand the concept. Also, add links to the adjecent milestones should be included.

- The milestone's image/symbol should be placed right next to its title.
- Each milestone should gain a real image (different from the symbol that is generated by you) that represents the invention, object or problem, if sensible. Please do not use images of people.
- Add dedicated transition pages between all milestones that concretely raise an issue not being solved by the current milestone but being solved by the following milestone. This should clearly help the audience and speaker help to move from one milestone to the next
- The mini game should be expandable to cover the entire screen.
- Each milestone should have 3 sections: (1) Problem (e.g. what was the problem at hand to be solved?), (2) Solution (e.g. how was the problem solved), (3) Relevance (e.g. what did it contribute to current day database? For example, count, schema/types, filter/where ...). Each section should not be visible right from the start in presentation mode, but should appear after mouse click or pressing forward arrow button.
- Each milestone should have the same structure/layout. 

## The Big Picture

Final overview which shows how all compenents work together to form a modern database. Should help the audience connecting all learned concepts together. Can be interactive and playful, too. Let's assume we build a database-like mascot that consists of all the elements/icons of the milestone that get's constructed piece by piece. Try to find a summarization that includes all of the milestone symbols as an unification story to build up how database work today and how each milestone plays its part.
